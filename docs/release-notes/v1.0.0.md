# Watchtower v1.0.0 release notes

Date: 2026-08-16

Package: `watchtower` @ `0.1.0` (CLI bin `wt`)

Ecosystem: Nirvana `1.0.0-alpha`

**Release gate status:** v1 release qualification is accepted through `REL-04`.
See the
[implementation tracker](spec/implementation/wt-v1-release/implementation-tracker.md).

## Summary

Watchtower v1 replaces the copied-template implementation-lane coordinator bootstrap
with a globally installable CLI, immutable packaged runtime, and per-lane
`.watchtower/lanes/<slug>/` execution overlay. All seventy-four v1
implementation batches are independently accepted. Release qualification
(`REL-01`–`REL-04`) reproduces end-to-end lane operation, concurrent and
multi-repository recovery, and security/packaging/endpoint conformance on the
installed package.

## Operator-visible capabilities

- **Global install:** `nvb dist` produces a self-contained package; `npm install -g ./dist` exposes `wt` on `PATH`.
- **Lane lifecycle:** `wt init`, `wt list`, `wt status`, `wt config show`, `wt doctor`, `wt watch`, and `wt upgrade`.
- **Coordinator read models:** `wt coordinator status|context|explain|index …`, `wt events tail|latest`, and `wt batch ready`.
- **Coordinator sessions:** durable operator sessions with lifecycle, budget, amendment, and confirmed apply boundaries (`wt coordinator session …`, `wt coordinator ask …`).
- **Knowledge install:** `wt skill install <codex|cursor|claude>` previews and installs the bundled coordinator knowledge pack.
- **Version reporting:** `wt version` reports CLI, runtime, knowledge, and lane-schema versions.

## Deferred or partial v1 surfaces

Normative status markers in [v1.md §10.3](../spec/v1.md#103-v1-commands) remain the
authority for commands still marked ⏳ or ❌. Notable deferred items:

- `wt doctor --report` redacted support export
- full-screen TUI render loop for `wt coordinator session attach`
- D1–D3 operator-turn endpoint execution through `wt coordinator ask`
- `wt coordinator hold place|release|list` command surface

Each deferred item is documented in the product spec rather than half-implemented.

## Upgrade and compatibility

- Lanes pin an immutable runtime/knowledge catalog; arbitrary project-root NVB tasks are rejected.
- Copied-template coordinator lanes are not discovered, imported, or upgraded.
- One repository may participate in many lanes; one lane may bind many repositories with exactly one control home.
- Reviewer acceptance remains semantic authority; Git publication is a separate recoverable process.

## Verification

Reproduce release qualification from a clean checkout:

```sh
nvb build
nvb test
nvb dist
```

End-to-end acceptance specs under `spec/e2e/` drive the **installed** `wt` binary.
See [operator quick start](../operator-quick-start.md) for day-one lane operation.
